# Bootstrap 6 migration runbook

The site runs on Bootstrap 5.3 (`www/vendor/`, pinned in `package.json`). Bootstrap 6 —
an alpha since 2026-10-08 — breaks most of what the site stands on: no `window.bootstrap`
global (ESM only), Modal → Dialog on a native `<dialog>`, Offcanvas → Drawer, Dropdown →
Menu, responsive classes `d-lg-none` → `lg:d-none`, colour utilities moving into
`.theme-*`, a rebuilt set of CSS variables without the `--bs-*-rgb` triplets, and Popper
replaced by Floating UI.

**Do not migrate on an alpha or beta.** This file is the plan for the day a stable v6 is
taken on deliberately. Until then three tripwires stop an accidental upgrade (see
[Replacement points](#3-replacement-points-in-the-code)): Dependabot ignores the major,
`make vendor` / `make vendor-check` refuse it, and the homepage spec's
"the bundle is Bootstrap 5 with its UMD global" test fails. If one of them fires, you are
here.

The JavaScript side was narrowed in advance: every read of the Bootstrap global, every
component class, every `*.bs.*` event name and the tooltip internals go through one file,
`www/js/bootstrap-access.js`. Most of the migration is therefore markup and CSS; the
script side is that file plus a handful of spec helpers.

## 1. `--bs-*` inventory

Every Bootstrap custom property our own stylesheets use, regenerated by
`node scripts/bs-vars-inventory.js --write` (`--check` tells whether this block is stale).
On migration day: regenerate, then walk the table against the v6 migration guide.

- **Reads** (`var(--bs-…)`) break silently when the variable is renamed or removed: the
  declaration becomes invalid at computed-value time and falls back to the inherited or
  initial value. Every one needs checking against v6's names.
- **Overrides** (`--bs-…:` declared in our CSS) retune Bootstrap's own rules. If v6 stops
  reading the variable, our override is simply dead and the component reverts to its v6
  default — again with no error. `common.css` carries the theme overrides
  (`--bs-body-bg`, `--bs-border-color`, `--bs-form-check-bg`, …) and the tooltip skin
  (`--bs-tooltip-*`).
- **Kind**: *theme* — public colour/shape tokens; *component* — scoped to one component;
  *internal* — what the bundle's markup relies on rather than a documented knob (the
  `-rgb` triplets, gone in v6, and the tooltip arrow geometry our arrow skin copies).

## 4. Open questions (cannot be settled before a stable v6)

- **Loading ESM without a bundler.** There is no build step (`deploy/README.md`). Options:
  an import map plus a module that re-exports the components onto a `window.bootstrap`-like
  shim the facade reads, or turning the facade into a module. The inline template blocks are
  already `type="module"`, but every application script is a classic deferred global. Deferred
  classic scripts and non-async module scripts share one queue and run in document order, so a
  module shim placed where the bundle is now would still run before `sidebar.js` and the
  calculator scripts — verify that this holds once it has imports of its own to fetch, because
  `profiles-ui.js` calls `setTooltipText()` at script load (`createProfilesUi()`), not from a
  `DOMContentLoaded` handler.
- **The tooltip guard.** #37474 is in code v6 rewrote. Check whether the defect survives; if it
  does not, delete `bootstrap-tooltip-guard.js` and its test in flight.spec.
- **Native `<dialog>` versus "one modal at a time".** `profiles-ui.js` relies on Bootstrap 5
  keeping one modal open at a time (see the comment at the `#pf-props-modal` hidden listener:
  editing is reached from the manage dialog, which closes first, and the hidden event reopens
  it). `dom-utils.js` stacks its alert/confirm dialogs on top of an open template modal. Both
  behaviours need re-checking on `<dialog>`, whose top layer and focus handling differ.
- **Breakpoint lg 992 → 1024 px.** The sidebar switches between the card and the offcanvas at
  `lg` (`sidebar.tpl`, `sidebar.css`). Decide whether 992–1023 px windows get the drawer.
- **Browser floor.** v6 targets Chrome/Edge 130+, Firefox 132+, Safari 18+. Measure the share of
  older browsers (Hawk, analytics) and write the result down here. If it is noticeable, the
  migration waits.
